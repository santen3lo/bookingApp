# 🔬 Laboratory Equipment Booking & Checkout System

Информационная система управления, бронирования и учета выдачи лабораторного оборудования.  
Проект поддерживает два режима работы: современный **графический интерфейс (JavaFX GUI)** с интерактивными визуальными компонентами и **консольный интерфейс (CLI)** с полным набором команд. В качестве постоянного хранилища используется реляционная база данных **PostgreSQL**.

## 🛠 Стек технологий

- **Язык программирования:** Java 21 (LTS)
- **Система сборки:** Gradle 9.x (Gradle Wrapper в комплекте)
- **GUI:** JavaFX 21 (`javafx.controls`, `javafx.graphics` через плагин `org.openjfx.javafxplugin`)
- **База данных:** PostgreSQL 14+
- **Драйвер БД:** PostgreSQL JDBC Driver 42.7.3
- **Безопасность:** Хеширование паролей алгоритмом SHA-256 (`PasswordHasher`)
- **Тестирование:** JUnit 5 (Jupiter 5.10.2) + JUnit Platform

## 🗄 Настройка базы данных

Система поддерживает два способа запуска базы данных: **через Docker Compose (рекомендуется)** или **ручную настройку локального PostgreSQL**.

---

### Способ 1. Запуск через Docker Compose (Быстрый старт 🚀)

В проект включён файл [`docker-compose.yml`](docker-compose.yml), который автоматически поднимает PostgreSQL версии 16 на порту `5432`, накатывает схему таблиц из [`shema.sql`](src/main/resources/shema.sql) и загружает тестовые данные из [`seed_data.sql`](src/main/resources/seed_data.sql).

1. Убедитесь, что у вас запущен Docker Desktop (или Docker daemon).
2. Выполните команду в корне проекта:
   ```bash
   docker compose up -d
   ```
3. База данных готова к работе! Контейнер сохраняет данные в volume `postgres_data`. Приложение автоматически подключается с настройками по умолчанию (`localhost:5432`, пользователь `postgres`, пароль `password`).

Остановить базу:
```bash
docker compose down
```
*(Чтобы полностью сбросить данные базы, добавьте флаг `-v`: `docker compose down -v`)*

---

### Способ 2. Ручная настройка локального PostgreSQL

Если вы предпочитаете использовать локально установленный сервер PostgreSQL:

1. Создайте базу данных:
   ```sql
   CREATE DATABASE postgres;
   ```
2. Выполните скрипт создания схемы:
   ```bash
   psql -U postgres -d postgres -f src/main/resources/shema.sql
   ```
3. Заполните тестовыми данными:
   ```bash
   psql -U postgres -d postgres -f src/main/resources/seed_data.sql
   ```

---

### ⚙️ Конфигурация подключения и безопасность

Приложение поддерживает несколько способов передачи параметров подключения (в порядке приоритета):
1. **Системные свойства JVM:** `-Ddb.url=... -Ddb.user=... -Ddb.password=...`
2. **Переменные окружения ОС:** `DB_URL`, `DB_USER`, `DB_PASSWORD`
3. **Файл конфигурации:** `src/main/resources/db.properties` (скопируйте из [`src/main/resources/db.properties.example`](src/main/resources/db.properties.example))
4. **Встроенные значения по умолчанию:** подходят для Docker Compose (`jdbc:postgresql://localhost:5432/postgres`, `postgres`, `password`).

> [!IMPORTANT]
> Файл `src/main/resources/db.properties` добавлен в `.gitignore` и не попадает в репозиторий, чтобы предотвратить утечку паролей. Для настройки скопируйте шаблон:
> ```bash
> cp src/main/resources/db.properties.example src/main/resources/db.properties
> ```
> и укажите ваш личный пароль (если он отличается от настроек Docker).

## 🚀 Сборка и запуск

### 🖥 Запуск графического интерфейса (GUI)
Графический интерфейс на JavaFX запускается стандартной задачей `run`:

- **macOS / Linux:**
  ```bash
  ./gradlew run
  ```
- **Windows:**
  ```cmd
  gradlew.bat run
  ```

При запуске появится окно входа в систему. Вы можете ввести реквизиты одного из тестовых пользователей или нажать **«Регистрация»** для создания новой учетной записи.

---

### 💻 Запуск консольного интерфейса (CLI)
Для запуска интерактивной консоли предусмотрена задача `runMain`:

- **macOS / Linux:**
  ```bash
  ./gradlew runMain --console=plain
  ```
- **Windows:**
  ```cmd
  gradlew.bat runMain --console=plain
  ```

Флаг `--console=plain` отключает анимацию статус-бара Gradle, обеспечивая удобную работу со стандартным вводом/выводом.

---

### 🧪 Запуск тестов
Для прогона набора модульных тестов выполните:
```bash
./gradlew test
```
Отчет о прохождении тестов в формате HTML будет доступен по пути:
`build/reports/tests/test/index.html`.

| Команда | Синтаксис и аргументы | Описание |

## 🎨 Особенности графического интерфейса (GUI)

Интерфейс разделен на три тематические вкладки:

1. **🧰 Вкладка «Бронирования» (Ящик инструментов):**
   - **Интерактивный ящик:** Приборы визуализированы карточками со стилизованными значками на текстурированном фоне инструментального ящика.
   - **Инспектор параметров:** При клике на карточку справа отображаются подробные сведения (тип, статус занятости, владелец, интервал).
   - **Управление:** Кнопки создания, переноса, отмены брони, а также быстрая выдача на руки прямо из ящика.

2. **📌 Вкладка «Выдачи» (Пробковая доска):**
   - **Визуализация стикеров:** Все открытые и закрытые выдачи представлены в виде карточек на стилизованной пробковой доске.
   - **Фильтр «Только открытые»:** Быстрое скрытие уже возвращенного инвентаря.
   - **Возврат оборудования:** Кнопка возврата с диалогом выбора состояния (`Исправен (OK)` / `Поврежден (DAMAGED)`).

3. **🔬 Вкладка «Инструменты» (Реестр приборов):**
   - Общая таблица инвентарного парка с русскоязычными наименованиями (например: *Микроскоп*, *Колба Эрленмейера*, *Весы аналитические*).
   - Кнопка **«➕ Добавить прибор»** для пополнения каталога новыми единицами.

## 🛡 Бизнес-логика и правила валидации

- **Контроль наложения временных интервалов:** Система блокирует создание пересекающихся активных броней на один и тот же инструмент.
- **Временные ограничения:** Запрещено создавать бронь на прошедшее время (`PastTimeException`), а дата окончания должна быть строго позже даты начала (`StartAfterEndException`).
- **Связь выдачи и брони:** Выдача на руки невозможна, если инструмент в этот момент удерживается по другой активной выдаче.
- **Безопасность сессии:** Отмена бронирования разрешена только создателю бронирования либо пользователю с административными правами.
- **Целостность данных:** Все изменения моментально фиксируются в PostgreSQL в рамках транзакций через JDBC.

## ❓ Частые проблемы и их решение (FAQ)

#### 1. Ошибка в IDE: `The import org.junit cannot be resolved`
* **Причина:** IDE (VS Code / Antigravity IDE / Eclipse Language Server) ещё не синхронизировала кэш classpath после добавления JUnit 5 в `build.gradle`.
* **Решение:**
  - Нажмите `Cmd + Shift + P` (или `Ctrl + Shift + P`).
  - Выберите: **`Java: Clean Java Language Server Workspace`** -> **`Restart and delete`**.
  - В IntelliJ IDEA: нажмите кнопку *«Reload All Gradle Projects»* на вкладке Gradle справа.

#### 2. Ошибка: `База данных недоступна / Не удалось подключиться к PostgreSQL`
* **Причина:** Сервер PostgreSQL не запущен, либо неверные параметры в `src/main/resources/db.properties`.
* **Решение:** 
  - Проверьте статус службы PostgreSQL: `brew services list` (macOS) или `sudo systemctl status postgresql` (Linux).
  - Проверьте логин, пароль и порт в файле [db.properties](src/main/resources/db.properties).

#### 3. Не отображаются картинки инструментов в ящике GUI
* **Решение:** Убедитесь, что каталог `src/main/resources/images/toolbox` содержит файлы `.png` и `drawer_bg.jpg`, и проект собран через `./gradlew build`.
